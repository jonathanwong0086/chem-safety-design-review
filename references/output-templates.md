# 诊断输出模板库

> 用途：诊断的各步边做边填这些表（输出汇总在第 11 步）。所有表都是诊断报告的标准产出件。
>
> **产出形式**：每一类产出写成一个单独的 markdown 文件（比如"章节完整性.md""缺陷清单.md"），再配一个索引文件 `00-索引.md`（顶部用 `---` 包起来的 `键：值` 块提供封面信息，正文按顺序列出各分章文件名）。第 11 步用 `python scripts/merge_md_to_docx.py 00-索引.md 报告.docx` 把整组合并成单个 Word 文档。完整示例见 [examples/report-sample/](../examples/report-sample/)。
>
> **填表的三条铁律**：
> 1. **先摆原文，再下结论**。每一条缺陷都必须先摘录专篇原文（带上页码、表号或具体位置），然后才给问题定性和依据。定位不到原文的缺陷，不成立。
> 2. **每条结论都要附证据源**。L1 给"标题#chunk 序号"，L2 给"路径:行号"，L3 给"内置卡[需复核]"。空泛的结论（比如只写"由以上分析可知"却没有数据支撑）不许入表。
> 3. **缺陷按"位置—事实—依据—建议"四要素书写**。位置精确到章节号/表号/附表号；事实含专篇原文摘录；依据落到标准条款号或独立复算结果；建议要可执行。模板5B、5C、9、10 及结论理由都遵循这个定式。

## 模板10 A/B/C 分级缺陷清单（第 11 步汇总）

| 缺陷ID | 分级 | 专篇原文摘录（页码/位置） | 缺陷描述 | 依据/复算 | 证据等级 | 整改建议 |
|---|---|---|---|---|---|---|
| D-01 | A | | | | L1/L2/L3 | |

**三个级别的定义**：

- **A 类（结论性、否决性）**：颠覆性的错误。比如核心设施章节缺项、标准用错导致整表无效（精细化工错用了石油化工标准）、辨识计算错误、程序硬伤（没有审查意见书、资质不符）、辨识出的危险却没有对应设施。
- **B 类（重要）**：依据章、概况章、结论章的关键内容缺失或空泛、数据闭环断裂、计算有偏差、图和文不一致。
- **C 类（一般）**：编辑质量问题（错字、编号、单位缺失、目录空挂）。但如果涉及资质或文号这类程序硬伤，要升为 A 类或 B 类。

## 模板11 通过性三档结论（第 11 步最终产出）

**先过程序性门禁，再谈技术评分**：给三档结论之前，先核下面这张"程序性一票否决门"检查表。**任一项命中，最终结论直接压到"不具备上会条件 / 不予通过"，不受技术质量高低影响**（程序硬伤和技术错误同等重要，见 M4）。

| 否决门触发项 | 命中判定 | 依据 |
|---|---|---|
| 安全条件审查意见书缺失 / 无文号 / 未附卷 | 命中/否 | 45 号令第十三条 |
| 依托设施未验收合格即投用（无"验收合格后再投用"前置条款） | | 三同时监管办法；属地未验收不得投用 |
| 审查权限层级错配（如涉高危工艺应省厅审却按市局报） | | 属地审查权限规定 |
| 备案证 / 许可范围与项目不符 | | 45 号令 |
| 命中 45 号令第十三 / 十九条其他不予通过情形 | | 45 号令第十三、十九条 |

命中项要按"位置—事实—依据—建议"四要素写明命中的是哪条法规。程序性门禁的结果来自 M4 的程序要件核查表（模板9）。

程序性门禁通过后，在缺陷清单的基础上给出总体结论，从下面三档里选一档，并说明理由：

1. **可上会 / 通过**：没有 A 类缺陷，B 类已经整改或者不影响核心结论。
2. **修改后上会 / 有条件通过**：没有 A 类，或者 A 类可以限期整改，需要列明整改项清单和复核方式。
3. **不具备上会条件 / 退回**：存在 A 类颠覆性缺陷（标准用错导致整表无效、核心设施缺失、辨识错误、程序硬伤），或程序性门禁命中。

**结论自洽的铁律（对应 M6）**：结论的严格程度要和查出的 A 类问题严重程度自洽——**如果查出了颠覆性错误却还给宽松结论，必须书面解释为什么**。

**L3 证据声明（证据等级是 L3 时强制加上）**：
> 本次诊断没有接入 WeKnora 规范库，所有标准数值都依据内置锚点卡（L3），属于**待复核的初判**；上会前必须逐条对照现行标准原文复核，据此确认本报告里"合标 / 超标 / 否决"的判断。
